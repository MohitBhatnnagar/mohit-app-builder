(spec with hidden checks + RUBRIC.md). Mohit as of the rebuild (verify_app, invariants, seed shape helpers).

Every failure was an escape: nothing Mohit checked had flagged it, and every Mohit warning the builders saw was fixed
before hand-over. So the gap to 95% is entirely about what Mohit can't see yet. All four escapes now have a fix in
Mohit (below); three are automatic checks, tested against the very apps the judges failed.

| Escape | App | Fix in Mohit | Kind |
| --- | --- | --- | --- |
| Client could claim tomorrow is "today" and tick it | habits | `platform/dates.ts`: `userToday(req)`, `isPastOrToday(day)`; guide section; `+14 hours` invariant idiom | building block |
| 6% of orders placed before the buyer's account existed | ticketing | data check: child rows dated before their parent was created (per-row cases warn; "all staff created at seed time" is a note) | automatic |
| Phone: table columns and nav links hidden inside sideways-scrolling boxes | lettings | screenshots at ≤600px flag nav links, table columns (or >80px) and selected items hidden in scroll boxes; chip strips allowed; `data-scroll-ok` opt-out | automatic |
| API stored impossible dates (2027-02-30, 2026-02-31) | lettings | data check: values `date()` can't parse; `isPastOrToday` validates real dates | automatic |

Builder friction also fixed: `create_project` slug, `fake.localDay`, ramp-warning wording, screenshot actions
write to the real DB (guide), `reset_data` confirm (guide), `confirm()` dialogs auto-accepted in screenshots, a
`select` action, nestable `transaction()` (a nested call used to crash).

**Next run:** the same specs (plus the other five) on the updated Mohit. With 10 checks per app, 95% means at most
one failure every two apps, so the full 8-spec set (80 checks) is the real measure.
